# Factory Scenario Lab

새 개인 포트폴리오 PoC입니다. 실제 SimPy 이산사건 공정 모델과 오프라인 로컬 Qwen의 자연어 대안 선택을 연결합니다. 모든 주문·공정시간·작업자 수·자격·교육은 합성 가정입니다. 실제 설비·회사 생산 데이터·개인 HR 정보와 연결하지 않습니다.

## 실행

검증 환경은 Python3.13, SimPy4.1.1, PyTorch2.6.0+cpu, Transformers4.49.0입니다. Python3.11 이상에서 실행하며, PyTorch CPU 배포를 사용하세요. 현재 호스트에는 CPU 모델 런타임과 모델 파일이 이미 있습니다. 코드가 런타임에 모델이나 외부 데이터를 다운로드하지 않습니다.

```powershell
python -m pip install simpy==4.1.1
$env:FACTORY_MODEL_DIR = (Resolve-Path '..\models\qwen2.5-1.5b').Path
python -X utf8 server.py --port 8766
```

프로젝트 디렉터리에서 실행합니다. `http://127.0.0.1:8766`을 엽니다. 모델 디렉터리는 `FACTORY_MODEL_DIR`로 지정할 수 있으며 기본값은 프로젝트 옆 `../models/qwen2.5-1.5b`입니다. 모델은 Qwen/Qwen2.5-1.5B-Instruct, revision `989aa7980e4cf806f80c7fef2b1adb7bc71aa306`입니다. 배포본에는 약3GB 모델 가중치를 포함하지 않을 수 있습니다. 모델 없는 환경에서 규칙 모드는 사용 가능하지만 LLM 모드는 실패를 명시하고 규칙으로 조용히 대체하지 않습니다.

## 모델의 실제 역할

LLM은 요청 문장과 고정된 후보 설명을 읽어 기준/로봇/교육/결합 중 선호 대안 라벨을 선택합니다. CPU `torch.float32` 실제 forward로 후보 단일 토큰의 로그릿을 평가하고, 선호 없는 프롬프트의 라벨 편향을 보정합니다. 검증 호스트는 AVX2 CPU이며 BF16 가속을 지원하지 않아 float32와 최대4개 CPU 스레드를 명시적으로 사용합니다. 실행 실패는 오류로 보고하며 다른 모델이나 규칙으로 대체하지 않습니다. 소수 예제는 고정 프롬프트에 포함하며, 학습·파인튜닝은 수행하지 않습니다. 자유 JSON 생성·공장 자율제어·산업용 모델 학습을 구현했다고 주장하지 않습니다.

수요 배율과 로봇·교육 금지는 명시적 파서와 스키마가 검증합니다. 모델은 이를 바꾸거나 새 설비 설정을 만들 수 없습니다. `selected_focus_id`는 실제 모델의 분류이고, `combined`를 선택한 경우 명시적 후처리로 로봇·교육·결합의 허용된 대안을 함께 비교합니다. `raw_output`은 실제 선택 라벨, `model.candidate_scores`는 실제 보정 점수, `latency_ms`는 측정 실행 시간입니다. 공정 수치와 교육 자원 지표는 모델 답변이 아니라 시뮬레이션 계산값입니다.

예시 입력:

- `주문량이 20% 늘었습니다. 인원 추가 없이 로봇 자동화와 검사 교육 대안을 비교해 주세요.`
- `로봇 추가 없이 검사 교육만 비교`
- `교육 없이 로봇 자동화만 비교`

수치 조건은 수요/주문량/주문 `0.5~1.8배` 또는 `N% 증가/감소/늘었/줄었` 한 개만 지원합니다. `로봇은 도입하지 말고…`, `교육은 하지 말고…`도 금지 조건으로 처리합니다. 작업자 수·교대시간·설비시간 등의 다른 수치 요청, 모호한 복수 수요, 개인 연락정보·지침 변경·외부 URL·실제 제어 요청은 거절합니다. 작은 모델은 선호를 오해할 수 있으므로 선택을 확인해야 합니다. 규칙 모드는 허용된 모든 대안을 비교하는 별도 기준선입니다.

## 실제 SimPy 공정

480분 동안 합성 주문이 `Uniform(6.4,9.6) / 수요 배율` 간격으로 투입됩니다. 운반→조립→검사의 자원 점유·대기를 모델링합니다. 주문별 고정 seed 변동계수는0.85~1.15, 재작업 플래그는10%입니다. 재작업은 조립4분→재검사6분으로 되돌아갑니다. 각 대안은 같은 seed의 주문·변동계수·재작업 플래그를 사용합니다.

| 대안 | 운반 평균 | 조립 평균 | 검사 자격 자원 | 전체 작업자 |
|---|---:|---:|---:|---:|
| 기준 |6분|10분|1명|4명|
| AMR·로봇 |2분|5분|1명|4명|
| 교육 |6분|10분|2명|4명|
| 결합 |2분|5분|2명|4명|

검사 기본시간은12분입니다. 가상 교육은 사전에8시간을 투입해 자격을 취득했다고 가정하며, 현장 교육 효과를 실증한 것이 아닙니다. 전체 작업자4명은 변하지 않습니다. 교대 인시는4명×8시간=32인시이고 교육8시간은 교대 외 별도 가상 투입입니다. 검사 자격 coverage는1/4=25% 또는2/4=50%입니다. 자동화 장비 운용·예외 대응에 필요한 실제 인력 비용은 모델링하지 않았습니다.

`metrics`는 seed0~9의 평균입니다. `summary`는 seed별 평균·최솟값·최댓값이며 신뢰구간이 아닙니다. `timeline`, 전체 `arrivals`, `completion_times`는 seed0의 실제 계산 기록입니다. UI는 이 기록으로 움직임을 표시하며 임의 애니메이션 수치를 만들지 않습니다. `trace`는120이벤트까지만 표시합니다.

완료·평균 대기·리드타임은480분 미만에 완료한 작업을 기준으로 계산합니다. 끝난 뒤 미완료 주문은 WIP로 남습니다. 대기는 자원 획득 전 시간을 합산하며 미완료 주문의 대기는 평균에 포함하지 않습니다. 자원 utilization은 horizon 내 점유시간/(480분×capacity)입니다. 수동 개입은 시작된 수동 방문 수입니다. 추천은 평균 완료 수가 최대인 비교 대안이며 동률이면 완료 작업 리드타임이 작은 대안입니다. 안전·비용·투자수익 최적화나 실제 사업 성과가 아닙니다.

## API와 저장

- `GET /api/status`: 실제 모델 파일/로드 상태와 SimPy 버전
- `GET /api/demo`: 네 대안의 고정 규칙 데모. LLM 실행 결과 아님
- `POST /api/plan {request,mode}`: `llm` 또는 `rules` 계획
- `POST /api/compare {plan_id}`: 저장된 검증 계획의10seed 실험
- `GET /api/experiment?id=...`: 저장한 전체 실험
- `GET /api/history`: 최근10실험 요약 `{items:[...]}`

합성4행 `data/workforce.json`의 ID·스킬·자격·교육 적격성을 검수해 검사 capacity와 coverage를 도출합니다. `experiment.hr`은 전체4명, 검사자격1→2명, 자격공백1명, 교육참여1명/8시간, 검수통과4행/오류0행, 원본SHA-256만 제공합니다. 개별 레코드는 API·UI에 보내지 않습니다. 과거 기록 재현을 위해 해당 원본 스냅샷은 SQLite의 실험행 `workforce_snapshot` 열에 별도 저장하며 aggregate는 실험payload에 저장합니다. 순위·채용·해고·개인 평가 판단은 구현하지 않습니다.

계획과 실험은 로컬 `data/factory-state.sqlite3`에 트랜잭션으로 저장합니다. 모델·SQLite에 각각 잠금을 사용하며 DB 연결은 매번 닫습니다. 서버는127.0.0.1만 바인딩하고 POST의 Host·Origin을 현재 loopback URL과 대조합니다. JSON4096바이트 한도, 엄격한 키/타입, 웹 루트 경로 제한을 적용합니다. CORS·파일 업로드·장비 제어·외부 요청 기능은 없습니다. 배포본에서 기존 개인 작업 DB를 공유하지 마세요.

## 검증 재현

```powershell
python -X utf8 -m unittest discover -s tests -v
python -X utf8 scripts/evaluate.py
```

평가기는 실제 단위/HTTP 테스트,40개 시뮬레이션(4대안×10seed), 표현을 바꾼 opposed-intent 요청과 금지·수치 요청, 실제 LLM HTTP→실험→재조회→재시작 DB 확인을 수행합니다. 아래 JSON에서 실행 결과와 실패를 확인합니다. 전체 평가 중 모델 로딩·CPU 추론은 시간이 걸릴 수 있습니다.

2026-10-07 검증 결과는24개 테스트 통과, Qwen1.5B 의미해석9/9 및 추론 전 거절4/4 통과입니다. 실제 LLM HTTP 계획·실험·재조회·이력 응답은 모두200이며 새 DB 연결의 실험값도 동일했습니다. 첫 의미해석은 모델 로딩과 중립 보정을 포함해44.03초, 이후8개는6.44~8.66초, HTTP LLM 계획은9.56초였습니다. 이는 이 호스트의 고정 사례 관찰값이며 일반적인 모델 정확도·응답시간을 뜻하지 않습니다.

- `data/evaluation-tests.json`: 실제 테스트 개수·출력·실행시간
- `data/evaluation-simulation.json`: 재현 가능한 전체 기본 실험
- `data/evaluation-initial.json`, `data/evaluation-llm-0.5b.json`: 초기 프롬프트/라벨 편향 및0.5B 최종5/9 의미해석 실패도 보존
- `data/evaluation-llm.json`: 전체 최종 사례, 실제 라벨·모델 점수·시간·성공/실패
- `data/evaluation-http.json`: 실제 LLM API 실행 및 저장 검증

고정 사례의 통과율은 운영 정확도나 산업용 성능 보장이 아닙니다. 시드 관찰 범위를 현장 개선 효과 또는 업무 시간 절감으로 표현하지 않습니다.

## 처음 실행하는 환경

```powershell
python -m pip install -r requirements.txt
python -X utf8 scripts/download_model.py
.\start.ps1
```

모델 다운로드는 공식 Hugging Face의 고정 revision 약3.1GB이며 최초 한 번 필요합니다. 모델 가중치는 ZIP에 넣지 않았습니다. 규칙 모드는 다운로드 없이 동작하지만 LLM 검증을 대신하지 않습니다. 그래픽 렌더러 MIT 고지와 실제 로고 출처·사용 조건은 web/vendor/THREE-LICENSE.txt와 docs/logo-assets/manifest.json에 포함합니다.

화면 종료 재생의 회귀 검증: `node --experimental-default-type=module tests/test-trace.mjs` (Node.js 필요). 스크린샷은 실제 브라우저 실행이며 포트폴리오에는 이미지 바깥 네 변에 연속 테두리와 여백을 둡니다.
