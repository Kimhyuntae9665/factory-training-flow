# 로컬 AI 목표 조언 연결하기

Line Lens의 AI 기능은 **로컬 LLM 서버**와 **Line Lens 서버**를 따로 실행합니다. 이 작업에서는 CPU에서 `Qwen3-4B-Q4_K_M` GGUF를 llama.cpp로 실행해 연결했습니다. 수동 3D 실험과 CSV 분석에는 모델 서버가 필요하지 않습니다.

## 1. 모델과 실행 파일 준비

[llama.cpp 공식 저장소](https://github.com/ggml-org/llama.cpp)의 설치 안내에 따라 `llama-server` 실행 파일을 준비하고, 사용 가능한 Qwen3-4B GGUF 가중치를 별도로 준비하세요. 모델의 원본 정보와 라이선스는 [Qwen3-4B 공식 모델 카드](https://huggingface.co/Qwen/Qwen3-4B)에서 확인할 수 있습니다. 원본 모델과 GGUF 변환·양자화 파일의 배포 출처는 구분해서 확인해야 합니다.

**이 소스 패키지에는 모델 가중치와 llama.cpp 실행 파일이 들어 있지 않습니다.** 아래 `models/Qwen3-4B-Q4_K_M.gguf`는 사용자가 준비한 파일을 가리키는 예시 상대 경로입니다. 실제 파일 위치와 이름에 맞춰 바꾸세요.

## 2. 모델 서버 실행

llama.cpp 실행 파일이 있는 폴더에서 실행합니다. 아래 예시는 CPU 실행이며, 옵션은 [공식 서버 문서](https://github.com/ggml-org/llama.cpp/tree/master/tools/server)를 참고했습니다.

```powershell
.\llama-server.exe --model "models/Qwen3-4B-Q4_K_M.gguf" --alias "Qwen3-4B-Q4_K_M" --host 127.0.0.1 --port 8767 --ctx-size 4096 --gpu-layers 0 --reasoning off --reasoning-budget 0
```

이 작업에서 성공한 실행은 위 설정에 `--threads 6 --threads-batch 6`을 추가했습니다. 스레드 수는 CPU와 다른 작업의 사용량에 맞게 정하며 6이 모든 PC의 최적값이라는 뜻은 아닙니다. 이 짧은 구조화 응답에는 사고 출력을 끈 설정을 사용합니다. Linux·macOS에서는 실행 파일을 `./llama-server`로 바꿉니다. 모델을 불러오는 동안 기다린 뒤 새 터미널에서 확인합니다.

```powershell
Invoke-RestMethod http://127.0.0.1:8767/v1/models
```

`data`에 로드된 모델 ID가 보이면 연결 확인이 가능합니다. 이 응답은 모델 목록 확인이며 목표 해석 추론을 마쳤다는 뜻은 아닙니다. 서버는 `/models`, `/chat/completions`, JSON Schema 형식의 구조화 응답을 지원해야 합니다. 일반 채팅 응답만 가능한 서버는 이 기능과 호환되지 않을 수 있습니다.

## 3. Line Lens 실행

소스 폴더의 `package.json`이 있는 위치에서 별도 터미널을 열고 실행합니다.

```powershell
$env:LINE_LENS_LLM_URL = 'http://127.0.0.1:8767/v1'
$env:LINE_LENS_LLM_MODEL = 'Qwen3-4B-Q4_K_M'
npm start
```

[http://127.0.0.1:8765](http://127.0.0.1:8765)을 열고 `AI 목표 조언`의 연결 표시를 확인합니다. 두 환경변수의 위 값은 코드의 기본값이므로 같은 설정이면 생략할 수 있습니다. 모델 별칭이 다르면 실제 `/models` 응답을 사용합니다. LLM 주소는 `http` 방식의 `127.0.0.1`, `localhost`, `::1`만 허용하며 외부 호스트·인증정보가 포함된 URL은 받지 않습니다.

앱 포트가 이미 사용 중이면 실행 전에 바꿀 수 있습니다. 이 작업의 검수에서는 다른 프로젝트와 겹치지 않도록 **8770**을 사용했습니다.

```powershell
$env:PORT = '8770'
npm start
```

이때 앱 주소는 [http://127.0.0.1:8770](http://127.0.0.1:8770)이며 모델 주소 8767과는 별개입니다. 모델 서버와 Line Lens 서버가 실행된 동안 사용할 수 있습니다.

## 4. 첫 요청 확인

`좀 더 빨리 물량을 만들고 싶어`를 입력하고 목표 해석을 요청하세요. 수량이 없는 문장이므로 해석 결과에 사용자 요청 수량을 만들어 넣지 않아야 합니다. 화면에는 별도 데모 기본값 **양품 1,000켤레·양품률 95%·공정 변경 최대 3개**가 표시됩니다. 작업자 모델에서는 피로 40·부하 90%의 가정 한도와 인력·속도·휴식 변경 허용도 확인합니다. 기본 작업자 설정은 중복 없는 네 프로필이므로 `이 목표로 504개 조건 비교`가 표시됩니다. 중복 프로필·변경 허용 여부·모델 사용 여부에 따라 실제 조건 수는 줄어듭니다.

시뮬레이터가 후보를 계산하고 로컬 LLM이 제공된 후보 ID와 허용된 설명 근거에서 선택합니다. 결과를 읽고 `이 후보를 3D 라인에 적용 ↑`을 누르면 기존 조작값에 반영됩니다. AI의 해석·후보 비교 단계만으로 설정이 바뀌지는 않습니다.

`시뮬레이터 계산 시간`과 `AI 목표 해석 / 근거 설명`은 서로 다른 실제 처리 시간을 표시합니다. 제품·시드·작업자 프로필이 같은 계산 캐시를 사용한 결과는 새로 시뮬레이션한 측정과 구분하세요. CPU·모델·요청에 따라 대기 시간이 달라지며, LLM 요청의 제한 시간은 단계별 120초입니다.

기존 v17의 작업자 모델을 끈 CPU·Qwen3-4B-Q4_K_M 브라우저 검수에서는 새 계산 **1.44초**, 목표 해석 **13.36초**, 후보 비교·허용 근거 선택 **24.16초**를 표시했습니다. LLM 처리 합계 **37.52초**에는 사용자의 목표 확인과 대기 시간을 넣지 않았습니다. 새 작업자 모델의 측정과 구분하며 평균 성능이나 다른 PC의 응답 시간을 보장하지 않습니다. 실행 조건별 기록은 [README](../README.md)에 있습니다.

## 오류와 한계

| 표시·상황 | 확인할 내용 |
|---|---|
| 로컬 LLM 미연결 | 모델 서버 실행, 8767 포트, `/v1/models` 응답, 환경변수의 주소 |
| 로컬 AI API 연결 실패 | Line Lens를 `npm start`로 실행했는지, 접속한 앱 주소·포트가 맞는지 |
| 구조화 응답 오류 | 서버의 JSON Schema 지원, 모델 출력 완료 여부, llama.cpp 로그 |
| 제약을 만족하는 후보 없음 | 목표 양품량·최소 양품률·변경 수·고정 요소를 확인하고 다시 비교 |
| 공장 조건이 바뀌었음 | 현재 제품·설정으로 후보를 다시 비교한 뒤 적용 |

연결 실패·시간 초과·잘못된 모델 응답에서는 AI 요청을 중단하며 기존 수동 기능은 유지합니다. LLM 응답을 흉내 낸 규칙 기반 설명으로 성공 처리하지 않습니다. 제약을 통과한 후보가 없으면 계산 결과를 알리고 LLM 비교 설명을 생략합니다.

개발 검수에서 4B 모델에 자유로운 응답을 허용했을 때 사용자 문장에 없는 수치와 계산으로 확인되지 않은 이유를 만든 사례가 있었습니다. 현재 구현은 원문에 직접 있는 숫자인지 검증하고, 후보별 허용 문장에서만 설명을 선택하게 제한합니다. 목표 해석은 여전히 잘못될 수 있으므로 사용자가 확인하는 단계가 필수입니다.

이는 자유로운 현장 진단이나 원인 추론 기능이 아닙니다. 최대 504개 공정·작업자 격자의 가상 모델 비교이며 실제 최적화·현장 생산 효과를 보장하지 않습니다. 피로·부하 한도는 안전 인증 기준이 아닙니다. [작업자 모델 설명](human-factors-model.md)의 계산식·한계를 읽고 값을 확인하세요. 별도 CSV 분석의 `AI 검토 프롬프트 .txt`는 다운로드용 텍스트이며 이 로컬 AI가 자동 실행하지 않습니다.

개발용 요청·응답 필드와 오류 코드는 [API 설명](advisor-api.md), 전체 계산 가정은 [README](../README.md)에서 확인할 수 있습니다.
